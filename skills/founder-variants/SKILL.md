# Founder Variants

Create real alternatives, not small wording changes.

Default to three variants unless the user asks for a different number.

## Variant Axes

Choose axes that actually change the approach:

- Problem-led
- Outcome-led
- Contrarian
- Data-led
- Story-led
- Founder-led
- Customer scenario
- Objection-first
- Short direct version
- Long explanatory version
- Platform-native rewrite

Do not create three versions with the same structure and different adjectives.

## Output

```markdown
## Variants: {asset or idea}

Input:
{brief summary}

### Version A: {axis}
{full variant}

Best for:
{situation}

Risk:
{weak point}

### Version B: {axis}
...

### Version C: {axis}
...

Recommendation:
Use version {A/B/C} because {reason}.
```

## Platform Guidance

- LinkedIn: clear hook, useful context, one point, light CTA.
- X: one sharp idea, minimal setup.
- Email: subject, first line, reason to care, one ask.
- Landing page hero: headline, subline, CTA, proof cue.
- Product Hunt: concrete product category, use case, founder note.
- Reddit/community: context first, link last or no link.

## Rules

- Label every variant by angle.
- Recommend one option at the end.
- If the input is too vague, route to `founder-office-hours`.
- If the user chooses a version, offer to tighten it instead of generating more.
