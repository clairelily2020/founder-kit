# Community Funnel

Use this when designing a community, contributor path, ambassador program, issue flow, user group, or public feedback loop.

## Funnel Shape

```text
Visitor -> follower -> user -> active user -> contributor -> advocate
```

Each step needs a clear next action.

## Entry Points

Good entry points are specific:

- "Try this demo."
- "Submit a use case."
- "Join the monthly build session."
- "Pick a good first issue."
- "Share your setup."
- "Request a teardown."

Weak entry points are vague:

- "Join our community."
- "Get involved."
- "Follow for updates."

## Contributor Path

For open-source or community-led products, define:

- good first task
- expected quality bar
- review owner
- response time
- recognition mechanism
- boundary between volunteer and paid work

## Community Rituals

Choose one repeatable ritual:

- weekly teardown
- monthly changelog demo
- user spotlight
- contributor office hours
- public roadmap review
- build-in-public recap

Do not create a community before you know the repeatable reason people return.

## Health Signals

Track:

- repeat participation
- comments from non-team members
- user-generated examples
- issues or questions with useful detail
- referrals from existing users

Follower count alone is not a community metric.
