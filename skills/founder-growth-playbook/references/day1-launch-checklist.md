# Day 1 Launch Checklist

Use this for open-source launches, Product Hunt launches, public repo launches, and small SaaS launches.

## Minimum Launch Surface

Before launch day, prepare:

1. A homepage or README that explains the product in one sentence.
2. A visible demo, screenshot, GIF, or example workflow.
3. Clear install or signup instructions.
4. A short launch post for each primary channel.
5. A tracking plan for traffic, signups, stars, replies, or demos.
6. A response plan for comments and early users.

## README Or Homepage First Screen

The first screen should answer:

- What is it?
- Who is it for?
- What does it replace or improve?
- What can I do next?

Avoid abstract mission language on the first screen.

## Launch Day Plan

```text
T-7 days: finalize positioning, screenshots, demo, FAQ
T-3 days: prepare channel posts, comments, email, tracking links
T-1 day: test install/signup/demo path
Launch day: publish, respond, collect feedback, update known issues
T+1 day: summarize results, fix obvious friction, follow up with engaged users
```

## Metrics

Pick one primary metric and two supporting metrics.

Examples:

- GitHub stars, installs, issues, discussions
- Product Hunt upvotes, comments, signups
- Landing page visits, CTA clicks, form submissions
- Post impressions, link clicks, replies

## Common Failure Points

- The product category is unclear.
- The demo does not show the value quickly.
- The CTA asks for too much.
- The launch post sounds like a press release.
- No one is assigned to reply to comments.
- Early feedback is collected but not turned into fixes.
