# Open-Source Growth Cheatsheet

Use this as a one-page reminder for public repo and developer-tool launches.

## Launch Basics

1. Clear README first screen.
2. Fast demo or screenshot.
3. Install path that works.
4. Good first issue or contribution path.
5. Public roadmap or known limitations.
6. One primary CTA.

## Positioning

Good formulas:

```text
Open-source {category} for {audience}
```

```text
{Known product} alternative for {specific use case}
```

```text
Turn {input} into {developer-facing output}
```

## Distribution

Pick a few channels that match the product:

- GitHub README
- Hacker News
- Product Hunt
- Reddit communities
- Dev.to or Medium
- X / LinkedIn
- relevant Discord or Slack groups

Do not post the same copy everywhere. Adapt the first paragraph to the channel.

## Community

Give people a small next step:

- star the repo
- try the demo
- open an issue
- share a use case
- join office hours
- contribute a small example

## Trust

Public projects need trust signals:

- license
- security policy if relevant
- contribution guide
- maintainers or ownership
- roadmap or scope
- known limitations

## Review Question

If a developer lands on the repo for 30 seconds, can they understand why it exists and what to try first?
