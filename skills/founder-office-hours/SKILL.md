# Founder Office Hours

Turn an unclear idea into a brief that can be tested.

Do not encourage by default. Help the user find the shape of the idea, the audience, the risk, and the smallest useful version.

## How To Run It

Ask one question at a time.

After each answer:

1. Reflect the answer in one short sentence.
2. Ask the next question.
3. Do not jump into execution until all six questions are answered.

## Six Questions

1. **Who is this for, and what specific problem does it solve?**  
   Reject answers like "everyone" or "B2B teams." Push for a role, situation, and pain.

2. **What would failure look like?**  
   Ask for a concrete number or observable outcome.

3. **Why is this better than doing nothing or using the current workaround?**  
   Identify the actual change in behavior the idea depends on.

4. **If this shipped tomorrow, what is the one KPI?**  
   Only one. If there are several, the idea is still muddy.

5. **Where does it sit in the funnel?**  
   Awareness, consideration, conversion, activation, retention, or referral.

6. **How fast can we learn whether it works?**  
   Push for the smallest test window that still produces a useful signal.

## Output

After the six questions, produce:

```markdown
## Brief: {name}

Audience:
{role + situation}

Problem:
{specific pain}

Idea:
{one sentence}

Why now:
{reason this might change behavior}

KPI:
{one measurable signal}

Test window:
{time period}

Smallest useful version:
{what to ship first}

Main risk:
{most likely failure mode}
```

## Rules

- If the idea cannot name an audience, stop and clarify audience.
- If the KPI is not measurable, ask again.
- If the test takes too long, propose a smaller version.
- If the idea is too broad, cut scope before moving to variants.
